The reframe

"Today's 3" was never universal — it was your ritual leaking into the platform. Other people don't run on it. Their tune should write its own ritual.

The previous proposal tried to make EEON adapt by switching modes inside a fixed founder-shaped layout. That was the wrong correction. The honest correction is structural: the home screen is not a layout, it's a function of the tune. The Karpathy LLM doesn't just pick which sections appear — it picks what rituals exist. Today's 3 is one ritual. Last Night's Dream is another. Single Intention is another. None are universal; all are persona-derived.

Below: the same architecture rendering two completely different homes. One was tuned by a founder/builder; one was tuned by a dream interpreter. They share two things — the capture button at the bottom, and the raw notes feed they can fall back to. Everything else is up to the tune.

What's already in the catalog

Today's 17 kinds — mostly founder-shaped.

Today's section catalog (HomeLayout.swift:18) was authored when the only user was a founder. The vocabulary leaks: priorityProjects, openDecisions, silentProjects. Some kinds happen to fit other personas (emotionalToneArc, recurringPatterns) but the assumption baked into A4 — "always include todayThree" — turns founder ritual into platform law.

  • todayThreefounder ritual · forced default
  • priorityProjectsfounder · ranks by momentum
  • openDecisionsfounder · unresolved >2 days
  • recurringPatternsgeneric · cross-article repeats
  • emotionalToneArcgeneric · dream-friendly
  • referenceResonancegeneric · canon matching

What needs to grow

New ritual primitives for the next personas.

For every new persona EEON serves well, the catalog gains 1-3 ritual kinds. The dream user needs lastNightsDream as their daily ritual and recurringImagery as their momentum surface. A meditator would need singleIntention. A researcher, currentInquiry. The catalog stays engineering-controlled (no generative UI), but it stops pretending the founder ritual is universal.

  • lastNightsDreamdream user · daily ritual surface
  • recurringImagerydream user · symbol clusters
  • singleIntentionmeditator · today's one thing
  • currentInquiryresearcher · the question you're sitting with
  • morningPromptjournaler · question to answer
  • gratitudeLogjournaler · what stayed with you

Two things stay universal.

  • capture button
    Mic + new note, anchored to the bottom dock. Every user captures the same way; that surface never changes.
  • recent notes feed
    Always available as the fallback surface. The user can always see what they actually captured, in chronological order.
  • knowledge layer
    Articles compile, RAG retrieves, embeddings cluster, the wiki index assembles. Same code, every persona.
  • extraction baseline
    Decisions, actions, commitments, people, topics still get extracted from every note — even when the persona doesn't surface them.
A platform with persona-defined surfaces, not a founder app with extension points. The Karpathy LLM is the interpreter that turns a person's words about themselves into the app they want.
