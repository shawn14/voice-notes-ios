The change

Tune EEON gets one structured field — Focus. A list of what matters right now, in priority order. Voice-input. Drag to reorder.

The previous tuning surface had two free-text fields: About You and What EEON Is For You. Both are stable across months — your role doesn't change weekly. Focus changes weekly. Burying it in a paragraph means re-typing the whole purpose to nudge a priority. Making it a structured list means you reorder by dragging a handle.

Same field, persona-shaped. For a founder it's a list of projects with weights. For a dream user it's a list of intents. The Karpathy LLM reads focus alongside profile + purpose and compiles the home accordingly.

01

Same shape, different content.

A founder's focus is a list of projects. A dream user's focus is a list of intents. The card is identical in structure — three rows, drag handles, weight chips, voice-input. The persona shapes the words inside; the architecture stays one component.

02

Drag to reorder.

Priorities shift. Yesterday StockAlarm was primary; tomorrow EEON might be. Reordering is a drag, not a re-write. Weight chips (Primary / Secondary / Tertiary) update automatically based on position. The home picks up the new order on next refresh — no recompile needed for ordering changes.

03

Voice in, structured out.

Tap "Add focus" or an existing item, hit the mic, say "StockAlarm — primary, where I want to spend most of my time." The transcribe pass extracts the item, the weight, and the optional note. You never type unless you want to.

Editing one item

Tap a row, get the same editor Tune EEON already uses.

Existing pattern — sheet slides up, big mic at the bottom, transcript appears above it. The only addition for focus items: three weight chips in the middle. No new component to learn.

The note field is optional. Most focus items will be one line. Some will have a clarifying sentence — "where I want to spend most of my time" — that helps the LLM weight more accurately.

What gets added to the schema.

One nullable structured field on the .purpose KnowledgeArticle. Voice & tone, layout, extraction schema continue to be LLM-compiled from the existing free-text fields. Focus is the only new user-declared structure.

profile (free text) user-declared · "About You" — paragraph
purpose (free text) user-declared · "What EEON Is For You" — paragraph
focusItems user-declared · ordered list of {content, weight, note?} — drives MomentumPicture, drift detection, and home prioritization
homeLayoutJSON LLM-compiled from above · which sections render and in what order
noteExtractionSchemaJSON LLM-compiled · what categories to extract from each note
voiceAndTone LLM-compiled · stylistic directive for rewrites + titles (shipped this batch)
Add a structured field only when the user changes it more often than what's around it, and when the system needs structure to compute against it. Focus passes both. Nothing else does, today.
